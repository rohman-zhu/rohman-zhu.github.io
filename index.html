access list 不生效

现象：你在 Advanced 中写了 location 规则，认证全部失效。

因为中文编码导致powershell脚本执行异常

Posted on 2026-08-08 In Windows Server , Powershell

故障描述

我在写一个Powershell脚本，里面有用正则表达式去截取字符串，正则表达式中包含中文；
我自己在Powershell终端中，复制粘贴执行，能截取到自己所需的字段；但是写到脚本里面，直接执行脚本反而获取到空值，非常诡异；
后面联合AI一起排查，AI给出几个错误排查方向后（这里Diss一下 DeepSeek），我逐行Debug，发现是正则表达式里面的中文字符没有被正确识别与执行！！

原因分析

终端默认读取的编码是 GBK ，经典’昆丁考’问题了;

解决方法

将脚本保存为 UTF‑8 with BOM

拓展阅读

问了AI: UTF‑8 与 UTF‑8 with BOM 的核心区别

有如下信息：

  1. BOM 是文件开头的 3 个字节（EF BB BF）。
  2. 对 PowerShell 解析的影响（核心）：Windows PowerShell（5.1 及更早）无 BOM -> 使用系统 ANSI (GBK)；有 BOM -> 使用 UTF-8。
  3. 没有头标记，回退使用系统默认 ANSI 编码（简体中文 Windows 即 GBK）,将 UTF‑8 字节按 GBK 解码 → 变成“施板滑”等乱码

凭据管理

在 Linux 系统上，SecureString 并不提供真正的加密保护，安全性会大幅降低；

  1. 在 Windows 上：SecureString 的内容会使用 Windows 的数据保护 API（DPAPI）进行加密，加密密钥与当前用户账户绑定，提供了较强的安全性；
  2. 在 Linux 上：SecureString 的内容不会被加密，而仅仅是进行了简单的编码或混淆（例如转换为十六进制字符串）。这意味着，任何能够访问进程内存或读取该字符串的人，都可以轻易地还原出原始文本;
