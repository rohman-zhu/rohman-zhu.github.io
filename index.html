AI模型消费选型-硬件本地部署VS各家MaaS

Posted on 2026-08-29 In AI

背景

最近在调研AI模型成本，看到 Mac mini M6、M5Pro 发布，还有就是部分DIY厂商提供AMD AI一体机，所以就推测一下本地化部署与MaaS的比较。

生成日期：2026-08-29

一、结论先行

2 万预算下，本地硬件跑不赢 MaaS，除非用途里有”数据不出门”这一条硬约束。 即使上到最高档 MaaS（火山 Pro 200 元/月），能替代云端的能力型硬件 5 年成本仍是它的 2 倍以上，且跑的是量化打折模型。默认主用途为 AI 编程辅助。

二、三笔账

2.1 成本账

硬件 价格 相当于 MaaS 多少个月
阿迈奇 128G 19899 千问 Lite 约 510 个月（42 年）
Mac Studio M5 Max 32G 19999 约 513 个月
Mac mini M5 Pro 64G 20499 约 526 个月
Mac mini M6 32G 11499 约 295 个月（24 年）

买任何一台硬件，等于一次性预付 24~42 年的云端订阅费。硬件跑量化打折模型，云端跑满血旗舰、持续换代，这笔账硬件必输。

2.2 能力账

“阿迈奇 96G 显存跑 235B”是营销话术：

  • 235B 指 MoE 模型全量参数（如 Qwen3-235B-A22B，实际激活 22B），非 235B 稠密模型。
  • 96G 显存放不下 Q4 量化的 235B 权重（约 130G+），只能靠 MXFP4 压到 120B 级别。实测能跑 120B 级模型，但”能部署”与”能日常用”是两回事。
  • 核心瓶颈是内存带宽：AI Max+395 仅约 273GB/s，比专业卡差一个数量级，跑大模型约 8~15 tokens/s，长 prompt、长上下文更慢。
  • 阿迈奇是杂牌迷你主机，AMD 本地推理生态（ROCm/Vulkan）成熟度不如 Apple，品控售后亦有风险。

Mac 侧：32G 的 M6 与 M5 Max 只能跑 14B~32B 量化，48G 的 M5 Max 封顶 70B。2 万内的 Mac 内存太小，不是”AI 部署机”，是”能顺便跑小模型的好电脑”。

2.3 数据账

这是本地部署唯一能翻盘的地方，且已有实锤：

  • 千问 Token Plan 个人版明文：模型输入与生成内容用于服务改进与模型优化（阿里云协议第 5.2 条）。用其跑代码，代码会进训练池。
  • 火山方舟个人 Coding Plan 数据条款未核实，需翻协议确认。
  • 本地部署数据绝对不出门，这是其独有价值。

三、分场景落点

场景 A：AI 编程辅助、日常问答、跑 Agent 工具（大概率场景）
选 MaaS，硬件不买，按使用强度选档：

  • 中高强度：火山方舟 Lite 40 元/月，每 5 小时约 1200 次、每月约 18000 次请求，前两月有折扣。千问 Lite（39 元/月）作备选，模型阵容更全（含 DeepSeek v4、GLM-5.2），但个人版数据授权条款需注意。
  • 重度：火山方舟 Pro 200 元/月，额度 ×5（每月约 90000 次请求）。即使 Pro 档，5 年 12000 元仍低于所有硬件，且跑的是满血模型。

场景 B：数据敏感、代码不能外流、或离线环境
千问个人版直接排除。先确认火山方舟数据条款；若也不干净，两条路：

  • 本地部署：2 万内只有阿迈奇能碰 120B 级别，接受 8~15 tok/s 慢速与杂牌风险。
  • 更务实：上企业版/团队版（千问企业版明确不用于训练）或用企业协议按量付费 API。

场景 C：本来就要买台电脑，顺带跑模型

  • 要最大本地模型能力：阿迈奇 128G。
  • 要省心全能的好电脑：Mac，但认清其跑不了大模型。
  • 折中：Mac mini M5 Pro 64G（20499，略超预算），能跑 70B 量化，生态成熟安静。

四、各家 MaaS 计费模式说明

国内平台截至 2026 年 7 月已分化出三条计费路线。计费模式决定”能不能用、会不会超支、会不会违规”，比价格更重要。

4.1 三条计费路线总览

路线 计费单位 代表平台 适用场景 能否程序化调 API
订阅制 Coding Plan 请求次数（5h/周/月三级窗口） 火山方舟、智谱 GLM、阿里云百炼 编程工具内交互式编码 多数禁止
Token Plan Credits / token 折算 阿里云个人版、火山方舟、MiniMax、腾讯云 编程工具 + 部分 Agent 多数禁止 API
纯按量付费 token DeepSeek 官方 Agent 后端、批处理、自动化 允许
企业积分制 积分（按 token 折算） 七牛云 企业业务集成 允许

4.2 订阅制 Coding Plan（按请求次数）

固定月费换请求次数，设 5 小时/周/月三级窗口，用完等刷新，不超支。

平台 Lite Pro/Max 月请求额度 模型覆盖
火山方舟 ¥40（首月约 ¥9.4） ¥200 Lite 18000 / Pro 90000 5 家厂商（豆包/GLM/MiniMax/Kimi/DeepSeek）
智谱 GLM ¥49 ¥149（Max ¥469） Lite 24000 / Pro 120000 GLM 系列，附 4 个官方 MCP
阿里云百炼 已停售 ¥200 90000 千问/GLM/Kimi/MiniMax，工具支持 14 款最全

共同机制：单次提问通常触发 5~30 次调用，额度按调用次数扣；多数明确禁止 API 调用，违规封禁。

火山方舟 Lite 计费详解（当前实际使用的套餐）

固定月费 40 元（活动期折扣，当前为前 2 月 2.5 折即 10 元），按”请求次数”扣减额度，不按 token 计费，不会产生超额费用。

限额窗口 Lite 额度 刷新规则
每 5 小时 约 1200 次 从首次请求起，每 5 小时自动刷新
每周 约 9000 次 每周一 00:00 重置
每月 约 18000 次 每个订阅月 1 日 00:00 重置
  • 请求次数 ≠ 提问次数：简单代码生成约 515 次调用，复杂重构约 1530 次甚至更多，全部计入额度。
  • 额度耗尽：等待对应周期刷新，不扣账户余额，无法临时扩容。
  • 使用边界：仅在支持的编程工具（Claude Code、Cursor、OpenCode、Cline 等）内、配置指定 Base URL 后生效；Base URL 配错会绕过限流、转为 API 计费并触发违规预警。禁止直接调 API。
  • 模型覆盖：五家厂商（Doubao-Seed、DeepSeek-V4、GLM-5.x、Kimi、MiniMax），可选 Auto 智能调度。

4.3 Token Plan（按 Credits / token 折算）

按 Credits 或 token 上限计量，消耗随模型、思考模式动态变化。

平台 入门档 主力档 计量
阿里云 Token Plan 个人版 Lite ¥39（2500 Credits/7 天） Standard ¥139 / Pro ¥499 Credits
火山方舟 Token Plan Small ¥40（22M token） Medium ¥200（111M）/ Large ¥500 / Max ¥1000 token 上限
MiniMax Token Plan Plus ¥49（周 15000 次） Max ¥119（周 45000 次） 请求次数 + token 上限

注：阿里云有两条线——Coding Plan（百炼，Pro ¥200，按请求次数）与 Token Plan（个人版，Lite ¥39，按 Credits）。本文 2.1 成本账与第五章对比所用的”千问 Lite 39 元”即 Token Plan 个人版。

4.4 纯按量付费（DeepSeek 官方）

DeepSeek 不做订阅，完全按 token 计费，无月费、无额度窗口、无抢购、无合规风险。V4-Flash 输入缓存命中低至 ¥0.02/百万 tokens，上下文 1M。适合用量波动大、做 Agent 后端的开发者。DeepSeek 模型也可通过火山方舟等第三方套餐使用。

4.5 企业积分制（七牛云）

面向企业的积分套餐（Enterprise S/M/B，¥2999~9999/月），积分按 token 折算，允许 API 调用，汇聚 DeepSeek/Moonshot/智谱/MiniMax 四家 25 个模型，兼容 OpenAI 与 Anthropic 接口。与个人 Coding Plan 不是同类产品，不应直接比价。

4.6 选型核心：先分交互式编码还是程序化调用

  • 在 Claude Code / Cursor 等工具里交互式编码 → 订阅制 Coding Plan / Token Plan（成本约为 API 的 1~2 折）。
  • 做 Agent 后端、批处理、自动化流水线 → DeepSeek 按量付费或七牛云，因为多数 Coding Plan 禁止 API 调用、违规封号。

入门档横向：MiniMax Plus ¥49（周 15000 次 / 月 600M token）同价位额度最高；火山方舟 Lite 首月 ¥9.4 试水成本最低、模型覆盖最广。主力档：MiniMax Max ¥119 周额度追平 ¥200 档；阿里云百炼 Pro 工具支持最全（14 款）。

各家套餐价格与额度调整频繁（阿里 Coding Plan Lite 已停售、MiniMax 已转 Token Plan、智谱涨价），下单前以官网实时页面为准。

五、价格比较（5 年拉齐）

计算参数

  • 硬件功率：300 瓦/台（统一口径）
  • 电费：0.75 元/度
  • 使用周期：统一拉齐到 5 年

注：300W 对 Mac 明显偏高（Mac mini M6 满载约 65W，Mac Studio 约 150~200W），阿迈奇高负载也难到 300W，故按 300W 计算属于偏向硬件的保守口径。

电费计算

0.3 kW × 24h = 7.2 度/天 = 5.4 元/天

  • 24 小时开机：约 1971 元/年，5 年约 9855 元
  • 每天 8 小时：约 657 元/年，5 年约 3285 元

MaaS 5 年成本

  • 千问 Lite：39 × 60 = 2340 元（按原价 60 元/月则为 3600 元）
  • 火山方舟 Lite：前 2 月 2.5 折，10×2 + 40×58 = 2340 元
  • 火山方舟 Pro：200 × 60 = 12000 元

Lite 档巧合同为 2340 元量级，Pro 档约为其 5 倍。

读表结论（300W 口径）

  1. 电费是隐藏大头：24 小时开机 5 年，电费 9855 元，接近甚至超过低配机购置价（Mac mini M6 电费是购置价的 86%）。越便宜的机器，电费占比越扎眼。
  2. 加入 Pro 后仍无一回本：最便宜硬件 Mac mini M6 5 年总成本 21354 元，仍是火山 Pro（12000 元）的 1.8 倍，且它跑不了大模型。
  3. 盈亏平衡点：硬件 5 年回本要求 MaaS 涨到约 356 元/月（对标 Mac mini M6）到 573 元/月（对标 48G Studio）。火山 Pro 仅 200 元/月，仍低于所有硬件的回本线。
  4. 换代贬值未入账：5 年后今天 2 万买的机器，面对 2031 年的模型大概率吃力；云端订阅的模型持续升级。

硬件账未计入的利好

以上将硬件当纯成本。若需求本就包含”一台电脑”（开发、办公、游戏），硬件有残值，部分购置成本可摊掉。但这不改变结论顺序：只要用途是 AI 编程，MaaS 先上；硬件仅在隐私 / 离线 / 折腾三个条件下进入候选。

方式二：按实际满载功率

300W 是统一上限，远高于这些机器的实际满载。按各机型真实满载功耗（墙测、含全部损耗）重算：

读表：

  1. 电费比 300W 口径腰斩：Mac 满载仅 65145W，5 年电费 21354763 元，不再是 9855 元。
  2. 对 Lite：差距 5.8~12.5 倍，结论不变。
  3. 对 Pro：最便宜 Mac mini M6 仅 1.1 倍，但其余能力型硬件仍 2.1~2.4 倍。注意 Mac mini M6 是 32G、跑不了大模型，价格接近 Pro 不等于能力接近。
  4. 满载是最坏情况：Mac 闲置仅 4~9W，若每天仅数小时推理、其余闲置，实际电费远低于表值（Mac mini M6 闲置 24h×5 年 ≈ 160 元）。真实电费介于”闲置”与”满载”之间。
  5. 阿迈奇 150W 为估算值（非官方墙测），不确定度最高。
  6. 盈亏平衡点：硬件 5 年回本要求 MaaS 涨到约 228 元/月（Mac mini M6）到 488 元/月（48G Studio）。火山 Pro 200 元/月仍低于所有硬件的回本线，即使用最高档 MaaS，硬件也不回本。

六、待确认

  1. 实际用途：纯 AI 编程，还是含隐私 / 离线硬需求？
  2. 火山方舟个人 Coding Plan 的数据使用条款。

七、实际使用记录

  • 2026-08-29：实际使用火山方舟，单个会话任务消耗了 87.47% 的 5 小时窗口额度（1200 次），即单会话 ≈ 636 次调用。
  • 意义：印证 agentic 会话（多轮工具调用）的真实调用量远高于静态估算。
  • Model:DeepSeek V4 Pro Ga

换算与判断：

项目 Lite Pro
单会话调用量 ≈ 636 次 ≈ 636 次
5 小时窗口可容会话数 1200/636 ≈ 1.9 个 6000/636 ≈ 9.4 个
月额度可容会话数 18000/636 ≈ 28 个 90000/636 ≈ 141 个
折合每个工作日（22 天） ≈ 1.3 个 ≈ 6.4 个

结论：

  1. 5 小时窗口是爆发瓶颈：连续跑两个重度会话就会在 5 小时内触顶，触发暂停。
  2. 月额度才是总量瓶颈：Lite 每天仅约 1 个重度会话的量，按当前 agentic 用法大概率不够。
  3. 升 Pro 后两者都充裕：5 小时窗口可容约 9 个会话，月额度约 6.4 个会话/工作日。
  4. 即便升 Pro（200 元/月，5 年 12000 元），仍低于任何硬件成本，选型结论不变。

5G 信号源不稳定，信号差

原始配置是:

  1. 工作频率：Legacy模式，信道 40（5200MHz）
  2. 无线电功率：0dBm（1mW）
  3. 许传统的 802.11b 速率

这个配置存在的问题：

  1. 传输功率为 0 dBm (1 mW)：这是最致命的问题。正常路由器功率通常在15-20dBm（约30-100mW）。0 dBm相当于把Wi-Fi信号“关闭”了，导致信号极弱，根本无法稳定桥接。
  2. 模式为 Legacy：这会强制Wi-Fi运行在802.11a/g标准，最大速率仅54Mbps。这完全浪费了5G频段的优势，且可能不支持中继所需的特性。
  3. 频宽未充分利用：你勾选了“强制40MHz频宽”，但受Legacy模式限制，实际速率已被锁死在54Mbps。在5G频段，应使用更高频宽（如80MHz）以获得更好的桥接速度。
  4. 802.11b是2.4G频段的老旧标准（最高11Mbps），在5G频段上完全没有用。勾选它会拖累整体网络效率，应明确禁用。

改进建议：

  1. 提高功率：在“无线电功率”处，将 0 dBm 改为 20 dBm（这是安全且推荐的最大值），然后点击“保存”。
  2. 更改模式：在“模式”下拉菜单中，将 Legacy 改为 N（仅11n）或 AC（仅11ac）。如果你不确定，建议选择 N/AC 混合模式。
  3. 调整频宽：取消勾选“强制40MHz频宽”。然后在上方“工作频率”处，将频宽直接设置为 80MHz。
  4. 允许传统的 802.11b 速率: 取消勾选;
  5. 重启生效：全部修改并保存后，重启路由器使设置生效。

2.4G 隐藏后，有一些米家设备离线

原始配置是：

  1. 工作频率：Legacy模式，信道auto；

问题：

  1. 模式为 Legacy：这会强制Wi-Fi运行在802.11b/g标准，最高速率被锁死在54Mbps。更关键的是，你下面勾选了“启用 256-QAM”，但256-QAM是802.11n（Wi-Fi 4）独有的技术，在Legacy模式下完全无效，这是一个明显的冲突设置。

修改建议：

  1. 更改模式：将“模式”从 Legacy 改为 N（或“N Only”）。这样能启用802.11n，解除54Mbps的速率限制。
  2. 固定信道：将“信道”从 auto 改为一个固定值。建议在 1、6、11 中选一个（这三个是互不重叠的信道）。你可以用手机APP（如“WiFi分析仪”）看看周围哪个信道干扰最少。
  3. 调整功率：将“无线电功率”从“自动”改为一个固定值（如 20 dBm），然后观察状态栏的“传输功率”是否正常显示。

2.4G 与 5G 信号相冲突

2.4G 选择 N 模式后，5G 桥接信号变得不稳定，时延上升至 400 ms；

核心原因：

  1. 2.4G切换到“N”模式，挤占了路由器的CPU资源，导致5G桥接处理不过来，延迟瞬间飙升到400ms。
  2. 之前（Legacy模式）：2.4G使用802.11g/b老旧标准，数据包简单，CPU几乎不需要额外计算，5G桥接可以独占CPU资源，所以延迟极低（2ms）。
  3. 现在（N模式）：启用802.11n后，如果开启了40MHz频宽或256-QAM，CPU需要做复杂的帧聚合（A-MPDU）和解调计算。CPU一忙，5G桥接的数据包就只能排队等待，延迟自然就暴涨到400ms。

整改方案：

  1. 既然IoT设备不需要高速，请把2.4G设置回“Legacy”模式（或“B/G混合”模式）。这不会影响智能插座的使用（它们本就只需几Mbps的速率），但能立刻释放CPU压力，让5G桥接恢复2ms的低延迟。

受限于小米路由器的性能，用于提供桥接能力的5G信号，如果调整成 N 模式，整体时延也会低一些；2.4G信号也会稳定一些；

测试基准：百度网盘下载速率能达到 5MBps ，有会员的情况下；
