vCenter services do not start due to VCHA settings in config file

Posted on 2026-10-01 In VMware , vSphere

故障现象

  1. VCSA刚执行了 ，重启VCSA；
  2. VCSA中的服务无法启动，执行 service-control –start –all 会卡在 HACore；

故障描述

重启后 vCenter 服务无法自动启动，service-control --status 显示大量服务处于 Stopped 状态（如 vmware-vcha、vmware-vpxd、vmware-vpostgres、vsphere-ui、applmgmt 等），service-control --start --all 启动卡在 HACore。

另一触发场景：从备份恢复 vCenter 后服务无法启动——备份时 VCHA 处于启用状态，而恢复目标上的 VCHA 已被移除。

判断方法

故障原因

vCenter 服务因配置文件中的 VCHA 残留设置而无法启动
__适用版本__：vCenter Server __7.x / 8.x / 9.x__（产品：VMware vCenter Server）

  • VCHA destroy（拆除）任务未完成，VCHA 设置残留在 /storage/vmware-vmon/defaultStartProfile（内容为 HACore）；
  • 从 VCHA 备份恢复后，vcha-post-restore.py 调用 /usr/lib/vmware-vcha/scripts/destroyVcha.py 清理 VCHA 配置，但脚本运行在”本身没有 VCHA 配置”的恢复后 vCenter 上时，清理流程无法完成（常见失败在 Revoke Certificates 一步）；
  • 结果 vmon 启动 profile 一直停留在 HACore，无法回退到 ALL，完整 vCenter 服务栈因此不被启动。

扩展知识

vmon 启动 profile（/storage/vmware-vmon/defaultStartProfile）

vmon（VCSA 服务总管）开机时读取该文件，决定启动哪一组服务。文件位于 /storage（VCSA 持久化分区，重启/升级后依然保留，因此残留的 HACore 会持续生效）。

profile 含义 正常出现场景
ALL 启动全部 vCenter 服务 独立 vCenter；VCHA 集群的 Active 节点
HACore 只启动 HA 核心服务（VCHA agent 及最小依赖） VCHA 集群的 Passive / Witness 节点

正常情况下该文件由 VCHA 流程自动维护，仅在出现本文故障时才手动写回 ALL。

vmware-vcha VCSA 8.x 上 vmon 的服务名，也是 RPM 软件包名 service-control / VAMI 中显示的名称
