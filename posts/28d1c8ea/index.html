黑群晖DSM意外断电排查记录

Posted on 2026-10-03 Edited on 2026-10-04 In 服务器与存储 , 存储 , NAS存储

故障现象

  1. 在点击电源按钮后，设备没有听到开机自检的蜂鸣器声音就自动断电了；
  2. 手动移除电源线，重新接通电源线，设备的开机自检蜂鸣器会响一声后就断电了；
  3. 移除掉接通的USB设备、网线，重新接通电源线，设备可正常开机，再接通网线正常；

二、关键发现

  1. NVRM 反复报”未发现 NVIDIA 显卡”：系统装载了 NVIDIA 内核驱动模块，但探测不到 GPU。经确认本机未安装任何 NVIDIA 独立显卡，可判定该报错为遗留驱动（如曾为硬解转码安装的 NVIDIA 驱动包）在缺少对应硬件时周期性探测产生的噪音，与本次掉电故障无关；同时据此排除”显卡短路引发过流”这一假设，将排查聚焦到 USB 与电源方向。

    另外注意：10-02 晚间 20:46 之前系统一直保持运行（NVRM 噪音正是运行中的佐证），此后约 24 小时无任何日志，说明异常掉电/断电发生在这个时间窗口内。

  2. 10-03 的完整日志实际是一次成功的启动（重要更正）：此前仅截取了日志开头（ACPI 表解析）片段，误判为引导早期掉电；补充完整日志后确认，本次引导一路走到网络、存储就绪且 DSM 正常进入。因此 10-03 21:09 这次开机是恢复后的正常运行，也印证移除故障 USB 设备后机器本身是健康的。

  3. 机型与引导环境确认：日志显示 Synology Hardware Version: DVA3221，且内核出现 redpill: loading out-of-tree module taints kernel——确认为黑群晖（RedPill 引导，DVA3221 镜像）。DVA3221 官方机型自带 NVIDIA GPU（用于深度学习/人脸识别），镜像因此内置了 NVIDIA 驱动；本机未插独显，驱动每次开机都会探测失败并输出 NVRM 报错，属预期行为，与故障无关（10-02 晚间每约 32 秒一次的报错是 DVA 相关服务在持续探测 GPU 所致）。

  4. **ACPI BIOS Warning: 32/64X length mismatch in FADT/Gpe0Block**：该警告在 AMI 主板上极为常见，属兼容性提示，与本次故障无关。

  5. synoboot 挂在 sd 6:0:0:0（疑似 USB 引导介质）：日志中引导盘 [synoboot] 并不在 SATA 的 ata1 SSD（32G）上，而是出现在独立的 SCSI 主机 6，极可能是一枚 USB 引导盘。结合”无任何 USB 设备仍异常关机”的事实，可以基本排除 USB 供电轨/外设短路，将怀疑重点转向电源与主板供电。

  6. 本次成功启动的日志中未出现任何 over-current / USB 报错：结合”无 USB 设备仍异常关机”的情况，进一步说明 USB 并非根因。

  7. **smpboot: this boot have memory training fail, last reason is 0x00**：内存训练失败提示。冷启动后偶尔出现可视为良性，但内存条接触不良/体质不佳同样可能导致开机或高负载时掉电，已列入初步结论第 3 条待排查。其余次要观察：ata2: send port disabled event（该 SATA 口未检测到盘，可能为空位或该口硬盘需检查）；WARNING: inconsistent syno gpio info, hdd detect（DVA3221 跑在非原厂硬件上的常见提示，可忽略）。

  8. 与故障现象 3 的重新解读：最初怀疑”移除 USB 设备”是开机成功的关键，但在未接任何 USB 设备的情况下 DSM 依然异常关机，证明 USB 不是根因。现象 3 中真正可能起作用的变量是”重新接通电源线”——PSU 的保护状态在断电后复位，重上电碰巧成功；USB 移除更可能是伴随操作（巧合变量）。

  9. 异常关机的时间特征（关键补充）：无 USB 设备时可正常开机并进入 DSM，运行约 40 分钟后异常关机，且间隔大致固定。”开机正常 + 固定间隔后断电”最典型的是温度积累型过热保护——负载恒定 + 散热不良时，每次冷启动到温度阈值所需时间相近，可表现为固定的 40 分钟间隔；其次是周期性软件机制（计划任务/硬盘休眠/UPS 误配置/Watchdog）；PSU 热失效也可近似表现为固定热积累间隔。

  10. DSM 提示 System booted up from an improper shutdown（关键证据）：每次启动 DSM 均提示上次为”异常关机后启动”，证实每次掉电都是硬件级直接断电（电源被直接切断），而非 DSM 主动关机/重启——由此基本排除计划任务定时关机、休眠设置等软件主动关机的可能，也排除”系统崩溃重启”类表现。

  11. OS 层面无 thermal 记录、读不到 CPU 温度（与平台特性吻合）：DSM 只能看到 HDD 温度，看不到 CPU 温度；掉电前日志也无 thermal 记录。结合主板为 J1900（Bay Trail-D）平台——该平台 CPU 温度不受 Linux coretemp 模块支持，属平台特性而非故障；同时也意味着过热保护若由 BIOS/主板层面触发，断电时 OS 完全无感知、不会有日志，”无 thermal 记录”不能排除过热保护。

  12. 主板为 J1900（Bay Trail-D，10W TDP 被动散热）：J1900 被动散热余量极小。但该 NAS 仅做数据存储相关业务、未启用任何 GPU/深度学习相关功能（NVRM 报错仅为 DVA3221 镜像内置驱动的后台低频探测噪音，不构成实质负载），因此”深度学习服务让 CPU 满载”的假设不成立，CPU 长期负载应处于低位——低负载下仅靠被动散热即可维持，CPU 过热只在散热硬件严重失效（风扇全停、散热片积灰堵死、硅脂干涸）时才可能发生。而早期”按电源键即断电/蜂鸣一声后断电”现象更偏向电源层（PSU 冷启动保护/老化）。故PSU 热失效/老化升为第一嫌疑，CPU 过热降级为需排查项。

  13. “网络/管理端下发关机指令”的可能性（已基本排除）：无论通过 DSM 计划任务、SSH、Synology 管理 API，还是第三方监控/运维平台（Zabbix、Prometheus、群晖 Central Management 等）发起关机，都属于操作系统层面正常关机流程，会写入 shutdown 日志，下次启动不会提示 improper shutdown。而本机每次均提示 improper shutdown，说明电源是被直接切断的，软件层面（含网络下发的关机指令）可基本排除。唯一需要确认的例外是”带外切断电源”类设备——如智能排插/PDU 远程断电、UPS 联动掉电——这类不走系统关机流程，需确认 NAS 是否接在可远程控制的插座或 UPS 上。

  14. 供电接口未完全插稳（重大发现，高度疑似直接根因）：拆机检查发现主板供电接口未完全插稳（接触不到位）。供电接口接触不良可统一解释此前几乎全部现象：① 开机瞬间断电/蜂鸣一声后断电——接触电阻大时，开机浪涌电流在接触点产生压降/打火，主板供电时序异常触发保护；② 重插电源线后正常——重新插拔使接触恢复；③ 运行约 40 分钟后断电——运行升温后接口受热膨胀、接触状态劣化到临界点，导致电压跌落/供电中断；④ 无 thermal 记录、硬件级直接断电（improper shutdown）——供电中断属硬件级掉电，OS 无感知。该发现与”现象高度偏向电源层”的判断一致，但根因可能不在 PSU 内部，而是供电物理连接不良。需插稳接口（听到卡扣”咔哒”声）后重新观察验证，并检查接口/插针有无氧化、烧焦痕迹（接触不良的接口会因接触电阻发热）。

三、初步结论（按可能性排序）

已确认本机未安装独立显卡，NVRM 报错为 DVA3221 镜像内置 NVIDIA 驱动在无卡时的预期噪音，显卡类硬件故障可排除。

关键事实链：无 USB 设备仍异常关机（USB 排除）→ 运行约 40 分钟固定间隔断电（热积累特征）→ DSM 提示 improper shutdown（证实硬件级直接断电，软件定时关机排除）→ 主板为 J1900（OS 读不到 CPU 温度、无 thermal 记录属平台特性，过热保护在 BIOS 层触发时 OS 无感知）。

  1. 供电接口接触不良（第一优先排查，拆机已确认存在）：主板供电接口未完全插稳，接触电阻大时可统一解释”开机瞬间断电/蜂鸣一声后断电””重插电源线后恢复””运行约 40 分钟后断电”等几乎全部现象（开机浪涌在接触点产生压降触发保护；运行升温后接口热胀、接触状态劣化导致供电中断）。处理：重新插紧全部供电接口（主板 24pin、CPU 供电、硬盘供电，卡扣到位”咔哒”声），检查接口/插针有无氧化、烧焦痕迹；插稳后重新观察是否复现。
  2. PSU 热失效/老化（并列待验证）：若接口插稳后仍出现 40 分钟固定间隔断电，再聚焦电源本身——本机负载低且恒定，电源内部老化元件升温触发 OTP 仍可解释固定间隔；给 PSU 吹风或换 PSU 交叉测试有效即实锤。
  3. CPU 过热保护（需排查）：J1900 被动散热余量小，且本机无 GPU/深度学习业务、CPU 负载低，仅当散热硬件严重失效（风扇停转、散热片积灰堵死、硅脂干涸）时才可能在低负载下积累到 BIOS 保护阈值；开箱直吹 CPU 散热片测试有效即可实锤，并同步检查散热硬件状态。
  4. 主板供电/VRM 老化（需排查）：AMI 老主板常见故障（VRM 异常、电容鼓包漏液、电源时序芯片老化），现象与 PSU 相似，交叉测试区分。
  5. 内存不稳定（需排查）：日志有 memory training fail 提示，建议重插、换槽、单条测试、memtest 排除。
  6. 周期性软件机制 / 网络下发关机指令（已基本排除）：improper shutdown 证实为硬件级直接断电，非 DSM 主动关机/定时关机，也非 SSH、管理平台等网络方式下发的关机指令（软件关机必然走正常关机流程）；仅需确认无”带外切断电源”设备（智能排插/PDU/UPS 联动）介入。
  7. USB 外设/接口短路（已基本排除）：无任何 USB 设备仍出现异常关机，USB 相关假设基本排除。

四、建议验证步骤

  1. 重新插紧全部供电接口（拆机已发现接口未插稳，最高优先）：将主板 24pin、CPU 供电、硬盘供电等所有电源插头重新插紧到位（卡扣”咔哒”锁紧），检查插针/接口有无氧化、烧焦痕迹；插稳后开机观察是否仍出现 40 分钟断电——若不再复现，则根因即为供电接口接触不良（可加扎带/固定防松脱）。
  2. 区分 CPU 过热与 PSU 热失效（关键对照实验）：① 开箱用风扇直吹 CPU 散热片跑一轮——间隔显著延长/不再断电 → CPU 过热实锤；② 单独给 PSU 吹风、清理电源进/出风口积灰再跑一轮——有效则 PSU 过热；③ 换一个已知良好的 PSU 交叉测试——恢复正常则 PSU 老化/故障实锤。
  3. 负载观察：通过 DSM「资源监视器」确认 CPU/磁盘负载是否如预期般低；若发现异常高占用进程（如 DVA 后台服务），停用相应功能观察是否不再掉电，排除负载驱动的热积累/供电触发因素。
  4. 摸温度定位热源：异常关机后立即分别触摸 CPU 散热片与电源外壳，烫手（难以持续按 3 秒）的一侧即主要热源。
  5. 检查散热硬件：J1900 散热片是否积灰/硅脂干涸/贴合松动、机箱风扇是否给散热片送风、电源风扇是否停转或异响、电源进风口是否积灰。
  6. 主板供电检查：主板电容鼓包/漏液、供电 Mos 过热变色、前面板 PWRBTN 排线接触不良。
  7. 内存排查：重插/擦拭金手指、单条轮流开机、跑 memtest；关注 memory training fail。
  8. 记录现场：每次异常关机后查看 /var/log/message 末尾与 DSM「日志中心」，记录掉电前最后一条日志与精确时间间隔（验证是否为固定热积累周期）。
  9. 最小化硬件排查：仅保留主板 + CPU + 内存 + 系统盘（若引导盘为 USB 则保留引导盘），逐级加回硬件观察是否复现。

五、待确认问题

  • 供电接口重新插稳后，是否仍出现约 40 分钟断电？（验证供电接口接触不良是否为根因）
  • 异常关机后立即触摸，CPU 散热片与电源外壳哪个更烫？（定位热源的关键）
  • 每次掉电的精确间隔是多少？（是否每次都约 40 分钟，还是 35~50 分钟浮动？）
  • 掉电前 /var/log/message 最后一条日志是什么？
  • DSM 中 CPU 占用情况如何？（确认平时负载是否如预期般低，是否有异常高占用的后台进程？）
  • 电源类型是什么（ATX / DC-ATX + 外置适配器）？额定功率多少？机器上有几块硬盘？（评估负载与电源裕量）
  • 机箱内风扇（给 J1900 散热片送风的风扇、电源风扇）是否都正常转动？
  • NAS 电源是否接在智能排插/PDU/UPS 上？是否有其他管理系统（监控/运维平台）可远程控制断电或关机？
  • 10-02 20:46 至 10-03 21:09 之间，机器如何断电？是否有主动关机操作？

六、排查结论（2026-10-04 更新）

根因已确认并修复：主板供电接口未完全插稳（供电接口接触不良）。

  • 2026-10-04 00:32 将全部供电接口重新插紧到位（卡扣”咔哒”锁紧）后重新通电开机；
  • 截至 2026-10-04 22:45，NAS 持续正常运行约 22 小时未再异常断电（此前故障间隔约 40 分钟），远超观察判定标准（数小时至一天不掉电），判定根因为供电接口接触不良，问题已解决。

机制回顾：供电接口接触不良 → 接触电阻大 → 开机瞬间浪涌在接触点产生压降/打火触发保护（”开机即断电/蜂鸣一声后断电”）；重插电源线使接触恢复（”重插后正常”）；运行升温后接口热胀、接触状态劣化到临界点 → 供电中断（”运行约 40 分钟后断电”）；供电中断属硬件级掉电，OS 无感知（无 thermal 记录、improper shutdown 提示）。

排查过程中确认无关/已排除的因素：NVIDIA 显卡（无独显）、USB 外设/接口短路、DSM 软件定时关机、网络下发的关机指令。

后续建议：

  • 用扎带/理线固定供电接口，防止运输或震动导致再次松脱；
  • 若接口/插针曾出现过氧化或烧焦痕迹，可观察一段时间，必要时更换电源线或接口；
  • 若未来复现，再按 PSU 交叉测试 / 散热检查顺序排查。
