Docker中的指令映射方案-hexo应用

Posted on 2026-11-22 In Linux

原始需求

我的 hexo 博客是部署在 Docker中的，平时使用的常用指令为 新建 “hexo new [博客文章]” 与 发布“hexo d”两个指令；这两个指令都是放置在Docker内执行的，我的宿主机是 user 账户，这是一个普通账户，我不希望 user 账户有太多的权限。

解决方案

hexo-new-safe 脚本解读

  1. exec：用后面的命令替换掉当前 shell 进程，而不是新开一个子进程;效果是：
  • 不多一层进程，信号（如 Ctrl+C）能直接传给 docker；
  • docker 的退出码直接成为脚本的退出码，sudo 能正确判断成功失败。不用 exec 写成 docker … 也能工作，但会多一层 shell，退出码和信号处理稍麻烦。
  1. “$@“：这是关键。它表示脚本收到的所有参数，原样、逐个传递。
  • 双引号必须加。”$@“ 会保持每个参数独立，即使参数里有空格也不会被拆开；写成 $@ 或 $* 则可能因分词和通配符展开出问题。
  • 举例：用户执行 sudo hexo-new-safe “My First Post”，脚本里 “$@“ 展开后就是两个独立参数：My First Post 作为一个整体传给 hexo new。
