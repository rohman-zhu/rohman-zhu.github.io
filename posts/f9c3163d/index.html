克隆失败-提示Invalid configuration for device 'XX'

Posted on 2026-01-27 Edited on 2026-10-01 In VMware , vSphere

背景

跨 vCenter 克隆一台 40TB 的虚拟机，耗时 3 天依旧失败，提示 Invalid configuration for device 'XX'。

本文内容基于 VMware KB 344928（Error “Invalid configuration for device ‘##’:” triggers failure of vMotion/Cloning for large Virtual Machines）。

故障现象

Shared-nothing vMotion（同时迁移计算和存储）或克隆（Clone）超大型虚拟机时，若迁移耗时超过 24 小时，任务失败，相关日志如下：

适用环境

  • VMware vCenter Server 8.x
  • VMware vCenter Server 7.x
  • VCF 9.x

原因

本次的主要原因是超时，导致分布式端口组的端口被释放。官方解释如下：

  • 此类迁移失败很可能是由于目标 ESXi 主机上缺少端口（port）
  • 对于任何迁移，vCenter Server 会为 DVS 端口保留 24 小时
  • 超过 24 小时后，端口保留到期，被 DvsMonitor 删除
  • 因此迁移到目标主机的虚拟机没有可连接的端口，迁移/克隆失败

解决方法

这是默认且符合预期的行为。要解决该问题，需要延长端口保留超时值，让迁移能够顺利完成（源和目标 vCenter Server 上都需要修改）：

补充信息

Q1：能否在不修改配置的情况下，让端口动态保留到任务完成？

A：不能。 平台架构对所有保留端口强制实施 TTL（Time-To-Live）计时器，以防止任务或系统在操作中途崩溃时造成永久性网络资源泄漏。vMotion 框架不能无限期锁定空闲端口，否则将违反”资源责任”这一基本设计原则；允许无限制的空闲锁定会带来资源饥饿（resource starvation）风险——孤立或停滞的任务可能永久占用虚拟交换机端口，耗尽集群容量。

Q2：该行为是否已在后续版本中修复或更改？

A：没有。 这是有意设计的资源保护行为，而非软件缺陷。主线版本默认保留阈值仍为 24 小时，以确保非活动分配被自动回收。

Q3：是否有办法让为迁移任务创建的 DVS 一直保留到任务完成（无论耗时多久），而无需在 vpxd 配置文件中添加超时项和值？

A：没有。 该流程的设计并不支持此需求。
