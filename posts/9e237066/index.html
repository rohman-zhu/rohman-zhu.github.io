小米路由器R4A刷OpenWRT折腾日记

Posted on 2026-08-23 In Linux

背景

小米4A千兆版想刷成OpenWRT试试；
路由器固件版本：2.30.28

参照文章：https://www.right.com.cn/forum/thread-8402524-1-1.html

实测可以成功刷新；

不过这个结论并不是说完全没有问题了，恰恰相反，刷机过程中以及刷机后里面的坑还多着呢；
如果你再问我还会不会再继续刷机，我不一定回答你“会”；而且我觉得有线比无线靠谱，至少在桥接上，还是得用有线！！无线桥接太容易出事了…

前置信息梳理

我有两个小米路由器 R4A , 平时的用法是主路由器放置在客厅，副路由器放置在卧室，两个路由器间通过无线桥接；

  1. 一台配置的 GigaDevice GD25Q128 （16MB）闪存芯片
  2. 一台配置的 EON EN25QX128(16MB) 闪存芯片

为什么这里要强调配置？原因就是这个芯片不同，决定了后面OpenWRT是否能成功刷机！！第一台我轻松刷机，按照教程处理就好了；第二台是灾难，死活刷机不成功，浪费我1天的时间；

核心：接口页面

位置： 网络/接口

分为两个大区 LAN 口（局域网） 与 WAN口（广域网）

防火墙相关的策略

LAN口默认应用的是 LAN Zone的防火墙策略；
WAN口默认应用的是 WAN Zone的防火墙策略；

配置相关的

目前我识别到的核心配置是 基本设置、物理设置

物理设置

点击 LAN 口的“修改”界面，进入到“物理设置”选项卡，可以看到 LAN口 其实是一个网桥：

这里表示 LAN 口内的二层是相通的；

基本设置

配置 IPv4 地址 与 子网掩码；

这里的 IPv4 不仅是 OpenWRT的管理地址，也是局域网内的所有节点的网关，粗略画一下链路图：

DHCP的地址也是在这个IP的子网内，因此这个IPv4地址仅用配置 IP与子网掩码地址；

找到一个方法是降级后再破解，所以找到一个 2.28.68 的固件，直接往路由器里面刷新，更新完成后，将路由器重启；

改用 ‘1.V1版开Telnet.bat’ 就可以顺利破解，运行脚本后根据提示：

备份当前固件

需要备份当前的固件信息

刷入 breed.bin

这里说一下breed的用途：

后续刷入固件失败导致路由器无限重启也不用担心，有Breed就可以万事大吉~想刷会官方镜像，也就是把Bootload换成官方的就好了

传入 breed.bin

  1. 在文件资源管理器地址栏输入: ftp://路由器ip/tmp
  2. 将安装包中的 breed.bin 文件 拷贝至 ftp://路由器ip/tmp 的窗口内；
  3. 在putty.exe输入 md5sum /tmp/breed.bin ；得到的结果应该是’24e62762809c15ba3872e610a37451a3 /tmp/breed.bin’

结果若不是 24e62762809c15ba3872e610a37451a3 一定不能贸然进行下一步！

刷入 breed.bin

  1. 执行指令：mtd write /tmp/breed.bin Bootloader
  2. 执行指令：reboot；
  3. 等待重启；

这里有一个关键变化：本次执行重启后，路由器的指示灯就失效了；后续设置需要在 OpenWRT 中配置；

备份编程器固件和eeprom

  1. 本地执行ping 192.168.1.1 ， 如果能联通就开始下一步 ；
  2. 浏览器访问 http://192.168.1.1 ；
  3. 进入“固件备份”，分别点击编程器固件、eeprom；

系统会自动下载两份文件，保存好即可；

刷入 OpenWRT 固件

开始进入最终环节了

  1. 浏览器访问 http://192.168.1.1；
  2. 进入“固件更新”，点击固件；
  3. 选择“openwrt-ramips-mt7621-xiaomi_mi-router-4a-gigabit-v2-squashfs-sysupgrade.bin”；
  4. 点击“上传”；
  5. 进入到“更新确认”页面，确认无误后就点击“更新”；

配置OpenWRT

路由器刷新完成后，默认地址会变更为 192.168.31.1 ；
浏览器访问 https://192.168.31.1 ， 进行配置操作；

默认密码是 root/password

5G 信号源不稳定，信号差

原始配置是:

  1. 工作频率：Legacy模式，信道 40（5200MHz）
  2. 无线电功率：0dBm（1mW）
  3. 许传统的 802.11b 速率

这个配置存在的问题：

  1. 传输功率为 0 dBm (1 mW)：这是最致命的问题。正常路由器功率通常在15-20dBm（约30-100mW）。0 dBm相当于把Wi-Fi信号“关闭”了，导致信号极弱，根本无法稳定桥接。
  2. 模式为 Legacy：这会强制Wi-Fi运行在802.11a/g标准，最大速率仅54Mbps。这完全浪费了5G频段的优势，且可能不支持中继所需的特性。
  3. 频宽未充分利用：你勾选了“强制40MHz频宽”，但受Legacy模式限制，实际速率已被锁死在54Mbps。在5G频段，应使用更高频宽（如80MHz）以获得更好的桥接速度。
  4. 802.11b是2.4G频段的老旧标准（最高11Mbps），在5G频段上完全没有用。勾选它会拖累整体网络效率，应明确禁用。

改进建议：

  1. 提高功率：在“无线电功率”处，将 0 dBm 改为 20 dBm（这是安全且推荐的最大值），然后点击“保存”。
  2. 更改模式：在“模式”下拉菜单中，将 Legacy 改为 N（仅11n）或 AC（仅11ac）。如果你不确定，建议选择 N/AC 混合模式。
  3. 调整频宽：取消勾选“强制40MHz频宽”。然后在上方“工作频率”处，将频宽直接设置为 80MHz。
  4. 允许传统的 802.11b 速率: 取消勾选;
  5. 重启生效：全部修改并保存后，重启路由器使设置生效。

2.4G 隐藏后，有一些米家设备离线

原始配置是：

  1. 工作频率：Legacy模式，信道auto；

问题：

  1. 模式为 Legacy：这会强制Wi-Fi运行在802.11b/g标准，最高速率被锁死在54Mbps。更关键的是，你下面勾选了“启用 256-QAM”，但256-QAM是802.11n（Wi-Fi 4）独有的技术，在Legacy模式下完全无效，这是一个明显的冲突设置。

修改建议：

  1. 更改模式：将“模式”从 Legacy 改为 N（或“N Only”）。这样能启用802.11n，解除54Mbps的速率限制。
  2. 固定信道：将“信道”从 auto 改为一个固定值。建议在 1、6、11 中选一个（这三个是互不重叠的信道）。你可以用手机APP（如“WiFi分析仪”）看看周围哪个信道干扰最少。
  3. 调整功率：将“无线电功率”从“自动”改为一个固定值（如 20 dBm），然后观察状态栏的“传输功率”是否正常显示。

2.4G 与 5G 信号相冲突

2.4G 选择 N 模式后，5G 桥接信号变得不稳定，时延上升至 400 ms；

核心原因：

  1. 2.4G切换到“N”模式，挤占了路由器的CPU资源，导致5G桥接处理不过来，延迟瞬间飙升到400ms。
  2. 之前（Legacy模式）：2.4G使用802.11g/b老旧标准，数据包简单，CPU几乎不需要额外计算，5G桥接可以独占CPU资源，所以延迟极低（2ms）。
  3. 现在（N模式）：启用802.11n后，如果开启了40MHz频宽或256-QAM，CPU需要做复杂的帧聚合（A-MPDU）和解调计算。CPU一忙，5G桥接的数据包就只能排队等待，延迟自然就暴涨到400ms。

整改方案：

  1. 既然IoT设备不需要高速，请把2.4G设置回“Legacy”模式（或“B/G混合”模式）。这不会影响智能插座的使用（它们本就只需几Mbps的速率），但能立刻释放CPU压力，让5G桥接恢复2ms的低延迟。

受限于小米路由器的性能，用于提供桥接能力的5G信号，如果调整成 N 模式，整体时延也会低一些；2.4G信号也会稳定一些；

测试基准：百度网盘下载速率能达到 5MBps ，有会员的情况下；

劫持域名

极米投影仪相关域名，添加到OpenWRT确实是要私人了，逐条添加也太累了；这个时候如果有dnsmasq的配置直接写入就好了…
