Booting a customized Windows Server 2025 virtual machine may be blocked by the black screen

Posted on 2026-09-21 Edited on 2026-10-01 In VMware , vSphere

概述

从模板（Template）使用 Guest OS Customization Specification（客户机操作系统自定义规范） 部署 Windows 11 24H2/25H2 或 Windows Server 2025 虚拟机时，VM 首次启动登录后可能出现持续黑屏（black screen），且无法完成自定义任务。

本文内容基于 VMware KB 400708（Booting a customized Windows 11 24H2/25H2 or Windows Server 2025 virtual machine may be blocked by a black screen）。

故障现象

使用 Guest OS Customization Specification 从模板部署虚拟机后，出现以下一个或多个问题：

  1. VM 未能按规范重命名（虚拟机自定义失败，无法重命名或加入域）

    该问题可能出现在 sysprep 和 generalize（泛化）之后、Windows VM 开机、客户机操作系统自定义成功完成后

  2. IP 地址未分配给网络适配器
  3. VM 无法加入 Active Directory 域
  4. 以管理员身份登录 Windows VM 后，explorer.exe 崩溃，桌面永不加载
  5. 首次启动登录后出现持续黑屏（persistent black screen）

受影响的 Windows 版本

  • Windows 11 24H2：高于 GA build 26100.1742 的版本
  • Windows 11 25H2：GA build 26200.6584 及以上
  • Windows Server 2025

适用环境

  • VMware vCenter Server 8.x / 7.x / 9.x
  • VMware vCloud Director 10.6.x
  • Aria Automation 8.18.x（原 VMware Aria Suite）

原因

该问题由 Microsoft Sysprep 行为的变更引起——操作改为在 SYSTEM 账户下执行，导致某些 AppX 包依赖无法正确初始化。

此外，如果黄金镜像/模板中禁用了 AppX Deployment Service（AppXSvc），Sysprep 泛化（generalization）会中止，导致自定义任务（重命名、IP、加域）无法触发。

解决方法

补充信息

  1. KB5082063 兼容性问题：如果操作系统版本历史中包含 2026 年 4 月 14 日更新（KB5082063），通过自定义规范的 RunOnce 运行 Add-AppxPackage 会持续失败。
    • 建议：使用最新版 Windows Server 2025 直接创建新的 OS 模板（或直接应用 2026 年 7 月 14 日更新 KB5099536），跳过 2026 年 4 月 14 日更新（KB5082063）
  2. 其他对客户有效的操作步骤：
    • 将模板转换为 VM → 开机 → 关机 → 再转换回模板，可能有助于模板部署的 VM 不再出现黑屏
  3. 建议：在自定义流程完成之后再执行 Windows 更新，避免更新行为改变部署前的系统状态，引发兼容性和启动问题（这是 Sysprep 的已知问题）
